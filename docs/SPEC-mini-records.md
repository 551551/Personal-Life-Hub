# mini-records：分场景业务规格（待审阅）

## 目标

适配现有自媒体、科研、健身、饮食、娱乐模块；以 `src/db/schema.ts` 的字段校验为基准，不删减已有子场景。

## 命令、结构与风格

遵循 `../tasks/plan.md` 的命令契约与代码约定。业务仓库在 `wechat/core/`，页面在 `wechat/pages/`，测试在 `wechat/tests/`。

## 场景边界

- 自媒体：制作阶段、发布计划、指标和复盘。
- 科研：项目、里程碑、文献、实验、论文、章节/修改项及父子关系。
- 健身：训练计划与动作，不新增体征数据功能。
- 饮食：餐次、数量、营养记录与汇总。
- 娱乐：自定义类别、进度；单独支持吉他曲目和练习计划。

## 数据与测试

依赖 mini-foundation 的提交接口；仓库验证全部外部输入，ID/日期/状态遵循现有规则。关联删除先展示影响并确认，不能留下悬挂引用。按任务清单逐场景测试非法值、父子引用、状态变更与保存回读。

## 成功标准

各场景增改删及特定操作完整；不会用统一待办列表替换业务内容。每个页面均通过处理器测试与真机操作，网站回归不受影响。
