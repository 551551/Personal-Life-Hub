# mini-data：备份与设置规格（待审阅）

## 目标

让用户可在网页、APK 和小程序间手动迁移自己的记录，并在操作失败时保住原数据。

## 命令、结构与风格

遵循 `../tasks/plan.md`。备份纯逻辑与平台文件适配分离，设置页面不直接调用浏览器 Blob 下载或 Capacitor 分享。

## 格式与接口

复用 `src/services/backup/backupSchema.ts` 的全部 17 张表，`appId: personal-life-hub`、`schemaVersion: 1`、导出时间与原格式一致。微信 AppID 仅用于工程配置。表数量已按实际 schema 纠正，验收逐项核对表名而非只比较数量。

依赖 mini-foundation、mini-records。导入流程：选择 → 限制大小 → 解析 → 校验格式与引用 → 展示影响 → 用户确认 → 整体提交 → 成功反馈。取消或失败不覆盖现有快照。导出含全部业务表；不能漏表后仍提示完整备份。

## 测试与成功标准

- 原格式生成的合成备份双向往返，所有字段保留。
- 错误版本、重复 ID、失效父子引用、超限文件、取消及提交故障均不损坏原数据。
- 设备实际文件选择、保存/分享和重新导入可用；仅有模拟测试不算完成。
- 清空有二次确认，本地清理风险和无自动同步提示清晰。

## 边界

不读取用户未指定的私人备份，不上传数据；文件 API 与兼容范围需通过官方资料核实。
