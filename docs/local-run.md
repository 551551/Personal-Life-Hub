# 本地运行、备份与恢复

## 首次安装

1. 安装 Node.js 20 或更高版本。
2. 在项目目录 `D:\软件\personal-life-hub` 打开 PowerShell。
3. 若没有 pnpm，先运行 `corepack enable`。
4. 运行 `pnpm install` 安装依赖。只有首次下载依赖时需要联网。

## 日常启动

在项目目录运行：

```powershell
pnpm start
```

浏览器打开 <http://127.0.0.1:4173>。停止应用时在 PowerShell 按 `Ctrl+C`。

数据按浏览器来源隔离。请始终使用同一个浏览器和 `http://127.0.0.1:4173`；不要在 `localhost`、其他端口和 `127.0.0.1:4173` 之间混用。

## 导出备份

1. 打开左侧“数据与设置”。
2. 在“备份与恢复”中选择“导出完整备份”。
3. 浏览器会下载名称含日期时间的 JSON 文件。
4. 将文件复制到可靠位置。备份包含全部 17 张业务表、设置、应用标识、结构版本和导出时间。

## 恢复备份

1. 打开“数据与设置”，选择“导入备份”。
2. 选择由本应用导出的 JSON 文件；单个文件上限为 10 MB。
3. 检查预览中的版本、导出时间和记录数量。
4. 输入确认文字并执行恢复。恢复会替换当前全部数据。
5. 页面重新加载后，检查首页、今日计划和至少一个来源模块。

格式损坏、应用标识错误、版本不兼容或字段无效的文件会在写入前被拒绝。写入过程在单个 IndexedDB 事务中完成，失败时原数据保持不变。

## 清空数据

“清空全部数据”位于设置页危险操作区，必须输入确认文字。清空不可撤销；执行前先导出备份。

## 升级

1. 先导出完整备份。
2. 停止本地服务。
3. 更新项目文件后运行 `pnpm install`。
4. 运行 `pnpm verify`；全部通过后再运行 `pnpm start`。
5. 使用原来的浏览器和 `127.0.0.1:4173` 打开应用，确认数据与聚合视图。

当前数据结构版本为 1。未来版本如变更结构，必须新增显式迁移并保持旧数据可读；不要手工修改 IndexedDB 或备份 JSON。

## 常见问题

- 页面没有旧数据：确认浏览器、协议、主机名和端口与之前完全一致。
- 端口被占用：先关闭占用 4173 端口的旧进程，不要随意改端口继续使用。
- 导入失败：保留原备份文件，根据页面错误检查文件是否完整及版本是否兼容。
- 清理浏览器缓存：普通缓存可重建，但清理“网站数据”会删除 IndexedDB，务必先备份。
